# Security and privacy

Do not open a public issue containing a secret, customer data, or an exploitable private integration detail. For a non-sensitive code defect, an issue with a synthetic reproduction is welcome. For sensitive reports, use GitHub's private vulnerability reporting if enabled; otherwise ask the maintainer for a private reporting channel without disclosing the details publicly.

Store real business work outside this checkout in a private location. Supply secrets through your provider's secure mechanism; never paste them into a task or commit them. Before publication, review the complete diff and run the local checker. If a credential was exposed, revoke or rotate it through its provider; deleting the text is not enough.
